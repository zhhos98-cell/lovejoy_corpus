# Frozen provenance register

Last synchronized: 2026-09-04  
Status: **GLOBAL DEFAULT FREEZE POLICY**

This register changes routing authority, not historical truth-value. Frozen files remain in Git and may preserve unique evidence, but they are not default working surfaces unless a living root control or terminal synthesis explicitly routes to them.

## Frozen by default

- filenames containing `batch`;
- filenames containing `round`;
- filenames containing `sweep`;
- filenames containing `delta`;
- filenames containing `freeze` or `handoff`;
- superseded draft versions not identified as current by `CURRENT_STATE.md` or `CANONICAL_INDEX.md`;
- abandoned comparative-actor frameworks, including the Brinton–Boas–Lovejoy `primitive` triangle and Batches 222/223;
- older state summaries superseded by living root controls;
- exploratory harvest/bibliography outputs that are not direct source witnesses.

## Frozen means

A frozen file may preserve unique provenance and may be consulted when a terminal synthesis points back to it. It must not override `CURRENT_STATE.md`, `CANONICAL_INDEX.md`, `PROJECT_ARGUMENT_MAP.md`, `QUELLENFORSCHUNG_CURRENT_GATE.md`, or the terminal synthesis set.

## Reopening rule

Reopen frozen material only for:

1. direct new primary evidence bearing on a live Lovejoy proposition;
2. contradiction in current evidence;
3. publication-level exact verification requiring the old audit trail;
4. source/version recovery that could change authorial ownership;
5. a demonstrated unique evidentiary fact omitted from the terminal synthesis and required by the current argument.

Conceptual completeness, typology building, vocabulary harvesting, or general period comparison are not sufficient reopening grounds.

## Practical effect

Ordinary research now follows:

> **living controls -> terminal synthesis -> exact primary/canonical witness -> audit trail only if needed**

rather than searching historical process notes to infer which one is current.
