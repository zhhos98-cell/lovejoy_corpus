## 5. Process provenance

Files containing `batch`, `round`, `sweep`, `delta`, `queue`, `freeze`, or `handoff` are normally historical/process material **unless explicitly routed above or from root living files**.

Do not delete a historical note merely because its status language is obsolete. Delete only when all three conditions hold:

1. it is genuinely supersession-only;
2. it contains no unique evidence or provenance needed in the working tree;
3. its state-bearing result has already been merged into a terminal/living file.

Git history remains the recovery layer.

## 6. Evidence labels

Keep these layers explicit:

- **diplomatic transcription** — visible manuscript wording directly read from image;
- **source-assisted / external-source collation** — printed/source material used to identify or constrain a reading;
- **editorial reconstruction / argument summary** — normalized explanation of what a page appears to do;
- **historical interpretation** — claims about training, transmission, method, politics, chronology, or later significance.

Never silently upgrade one layer into another.

## 7. Naming rule

For new notes, prefer object-first lowercase `snake_case` names with ISO dates and an explicit function/status where useful. Preserve archival identifiers such as `MS38_...` when they are the actual object key.

Existing heavily cited legacy paths remain stable unless a migration is clearly worth the reference cost.
